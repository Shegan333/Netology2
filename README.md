# Анализ эффективности интернет-магазина

Итоговая работа на Python: интерактивный дашборд Streamlit по данным из
предоставленного архива `artifacts_csv.zip`. Основной код — **app.py**.

## Запуск

Нужен Python **3.11 или новее**. Зависимости зафиксированы в `requirements.txt`.
В терминале в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте адрес, который напечатает Streamlit (обычно http://localhost:8501).
Остановка: Ctrl+C в терминале. При уже настроенном окружении можно использовать
`streamlit run app.py`. CSV должны находиться рядом с `app.py`; пути не зависят
от текущей рабочей папки терминала. Настройки темы и отключение телеметрии —
в `.streamlit/config.toml`.

## Что есть в приложении

- **Ключевые показатели:** уникальные заказы, выручка, покупатели, средний чек;
  дополнительно выручка по календарным дням.
- **Визуализация:** топ-10 товаров по выручке, выручка и доли категорий,
  заказы по дням недели. Можно переключиться на среднее число заказов
  за календарный день соответствующего типа.
- **Аналитические выводы:** автоматически пересчитываются при фильтрации;
  учтены несколько лидеров при равенстве показателей и ограничения данных.
- **Сырые данные:** объединённая таблица, выгрузка текущей выборки,
  три исходные таблицы, пропуски, типы и отчёт об очистке.

Фильтры периода и категорий общие для всех четырёх разделов.
Пустой список категорий означает пустую выборку. Кнопка сброса возвращает все
категории и весь доступный период. Отчёт о качестве всегда описывает полные
исходные файлы и подписан отдельно.

## Подготовка и расчёты

1. Загрузка трёх CSV через `@st.cache_data`. Ключ кеша включает время изменения
   и размер файлов, поэтому после замены CSV и обновления страницы данные перечитываются.
2. Проверка обязательных столбцов, удаление пробелов и точных дублей.
3. Приведение ID к целым положительным числам, дат — к datetime, цен и
   количества — к числам; ошибки преобразований становятся пропусками.
4. Позиции с некорректными order_id, датой, количеством или ценой исключаются
   и показываются с причинами. Количество должно быть целым и положительным,
   цена — неотрицательной. Нулевые продажи разрешены.
5. Два `left merge`: с users по user_id, с items по item_id.
   `validate="many_to_one"` и проверка уникальности ключей не позволяют умножить
   выручку из-за конфликтующих справочников. Пропущенные ключи справочников
   исключаются, чтобы Pandas не соединял пустые ключи между собой.
6. Неизвестные покупатели и товары сохраняют продажи; текстовые атрибуты
   заполнены «Неизвестно», название товара — его ID. Даты регистрации
   и справочные цены без значения остаются пропусками.

**Формулы:**

- Выручка позиции = quantity × price_per_unit; общая выручка = сумма позиций.
  Цена округляется до копеек, суммы хранятся и складываются в целых копейках.
- Заказы = число уникальных order_id, а не число строк.
- Покупатели = число уникальных непустых user_id в выборке.
- Средний чек = выручка / число заказов. При фильтрации категорий это выручка
  выбранных позиций на заказ, в котором есть эти позиции.
- Товары и категории агрегируются через groupby; дни недели — через pivot_table
  с nunique(order_id). Для среднего по дням недели знаменатель — количество
  соответствующих календарных дней в выбранном периоде, включая дни без заказов.

Одинаковые позиции целиком считаются дублями, поскольку в исходных данных нет
line_id. Разные товары одного order_id допускаются, если покупатель и время
заказа совпадают. Для иной структуры заказов это правило следует согласовать
с владельцем данных.

## Контрольный результат исходной выборки

В архиве **40 заказов, 25 покупателей, 20 товаров**, период — **1–10 февраля 2024**,
а не полный месяц.

| Показатель | Значение |
| --- | ---: |
| Выручка | 97 541,94 ₽ |
| Заказы | 40 |
| Покупатели | 25 |
| Средний чек | 2 438,55 ₽ |
| Выручка категории «Электроника» | 53 269,94 ₽ |
| Лидер по выручке | Ноутбук ASUS VivoBook: 14 995,00 ₽ |

`base_price` не участвует в выручке и не трактуется как себестоимость.
Валюта принята за рубли. Возвратов, статусов, затрат, посещений и рекламных
расходов нет; прибыль, конверсия и ROMI не рассчитываются.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются независимый расчёт сумм через Decimal из CSV, сверка агрегатов,
многопозиционный заказ, исключение ошибок, неизвестные ссылки, дубли,
пустая выборка и нулевая выручка. AppTest проверяет запуск, фильтрацию,
сброс и переключение представления дней недели.

Справка: [кеширование Streamlit](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_data),
[AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).
